# Workers와 Windows Node의 연결 보안 증거

## Cloudflare API 재검토

| API                        | 지원되는 성질                                                                    | 출시 판단                                                                                                                                                                                                                                                                                                                                                 |
| -------------------------- | -------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Workers fetch / Request    | URL 호스트의 HTTPS, manual redirect 옵션                                         | 최종 피어와 사전 DNS 결과의 결속 증거가 없다. 사전 DoH 확인을 별도 fetch의 증명으로 사용할 수 없다. [Request](https://developers.cloudflare.com/workers/runtime-apis/request/)                                                                                                                                                                            |
| resolveOverride            | URL과 대체 호스트가 모두 자신의 zone에 있을 때 대체 hostname 해석                | 일반 제3자 공식 사이트의 IP pin이나 연결 피어 검증에 사용할 수 없다. [resolveOverride](https://developers.cloudflare.com/workers/runtime-apis/request/#requestinitcfproperties)                                                                                                                                                                           |
| TCP connect() / startTls() | 아웃바운드 TCP 및 TLS upgrade, 타입에 expectedServerHostname, 피어 필드는 선택적 | 공개 workerd 구현의 outbound remoteAddress 설명은 connect() 입력이다. 타입과 로컬 TLS 동작으로 관리형 edge 피어나 SNI 검증을 입증할 수 없다. Cloudflare IP로의 TCP 연결도 제한된다. [TCP](https://developers.cloudflare.com/workers/runtime-apis/tcp-sockets/) · [런타임 소스](https://github.com/cloudflare/workerd/blob/main/src/workerd/api/sockets.h) |
| Workers Node.js DNS/HTTPS  | DNS 호환 모듈 및 HTTPS 요청                                                      | DNS 결과만으로 연결을 고정할 수 없다. HTTPS 문서는 servername, rejectUnauthorized, ca 등을 미지원으로 명시한다. [DNS](https://developers.cloudflare.com/workers/runtime-apis/nodejs/dns/) · [HTTPS](https://developers.cloudflare.com/workers/runtime-apis/nodejs/https/)                                                                                 |
| Service Binding / RPC      | 공개 URL 없이 신뢰된 Worker 사이 호출                                            | 호출 경계 분리에 활용할 수 있다. 호출 대상 역시 자기 egress와 TLS를 증명해야 한다. 공개 egress 프록시로 동작하는 코드는 추가하지 않았다. [Service bindings](https://developers.cloudflare.com/workers/runtime-apis/bindings/service-bindings/)                                                                                                            |

관리형 edge에 대한 원격 실증을 실행하지 않았다. 공개 소스에서 확인한 의미는 문서와 타입의 간극을 설명하며 실제 edge 계측과 구분한다.

## 채택한 로컬 경계

- Collector의 승인·정확한 hostname·443·HTTPS·경로·robots 검사는 각 홉에 적용한다. 원본 URL의 userinfo·IP·비정상 포트·Unicode authority·encoded authority 및 구분자·encoded dot segment를 거부하며 명시적으로 등록한 ASCII punycode만 허용한다. Redirect는 원문 검사를 먼저 하고 같은 origin·검토 경로·횟수 제한을 적용한다.
- Windows 시스템 resolver가 반환한 주소를 전부 확인한다. 1–32개 중 하나라도 비공인 IPv4, 특수 주소 또는 IPv6이면 해당 조회를 거부한다. IPv6 허용은 별도 심사이며 IPv6-only/DNS64/혼합 응답은 보수적으로 차단한다. 안전 판정은 승인 네트워크·신뢰 OS와 TLS trust store를 전제로 한다. [IANA IPv4 등록부](https://www.iana.org/assignments/iana-ipv4-special-registry/iana-ipv4-special-registry.xhtml)
- 열려는 소켓에는 검토된 숫자 IPv4와 443만 전달하며 원래 hostname을 SNI로 지정한다. 기본 PKI와 hostname 검사, TLS 1.2 이상, 커널 피어 일치 후에만 HTTP를 시작한다. 연결·세션을 재사용하지 않는다. peer 실패, TLS 실패, DNS 실패의 경우 일반 fetch나 다른 주소로 전환하지 않는다. [Node TLS](https://nodejs.org/docs/latest-v22.x/api/tls.html)
- 5초 요청과 30초 수집 단계, 8회 이하 요청, 16 KiB 응답 헤더, wire 및 해제 각각 256 KiB, 압축 backpressure를 유지한다. 200 이외 응답은 본문을 읽지 않고 필요한 Location·validator·Retry-After만 전달한다. 요청에는 지정 헤더만 실어 인증·Cookie·proxy 헤더를 전달하지 않는다.
- lease, URL, 허용 호스트, 최소 간격, 형식, robots·약관 검토 일자와 원래 승인 레코드를 홉마다 재확인한다. Node는 DNS 반환 뒤에도 확인한다. 가져온 응답은 정책 검사를 다시 거치며 저장 배치는 최신 승인 범위와 owner/lease가 같은 경우만 적용한다. 오래된 승인 또는 지문 없는 체크포인트는 후보에 반영하지 않고 최소 접근 간격을 충족한 뒤 재개한다. 이미 시작한 네트워크 요청의 바이트는 철회할 수 없으므로 후속 요청과 저장을 차단한다.
